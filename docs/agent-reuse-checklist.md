# 可复用 Agent 沉淀自查清单

本文档用于每次项目构建完成后的复盘：判断本轮构建过程是否值得沉淀成可复用 Agent、脚本、运行手册或自动检查流程。

## 每次构建完成后的固定自查

1. 本轮是否出现重复性流程？
   - 例如部署检查、构建后重启预览、资料上传验证、角色权限验证、移动端兼容检查。

2. 本轮是否依赖明确输入并产生稳定输出？
   - 输入可以是环境变量、页面路径、角色、接口地址、文件路径。
   - 输出应是通过/提醒/错误、修复建议、操作步骤或报告。

3. 本轮是否有可标准化的验收口径？
   - 例如 `npm run build` 通过、`/api/health` 返回 `ok:true`、CSS 资源返回 200、无 Hydration Error。

4. 本轮是否适合沉淀？
   - 高频、低风险、规则清晰：优先沉淀为脚本或 Agent。
   - 低频但高风险：优先沉淀为 runbook。
   - 需要人工判断较多：沉淀为检查清单，不急于自动化。

## 沉淀等级

- `脚本`：可由命令稳定执行，例如部署健康检查、生产配置核对。
- `Agent`：需要结合上下文做判断、汇总和建议，例如构建完成复盘、浏览器兼容验收、服务器上线体检。
- `Runbook`：步骤固定但涉及人工操作，例如腾讯云备案后 HTTPS 配置。
- `清单`：暂不自动化，但每次构建必须人工核对，例如手机端微信浏览器实测。

## 当前已沉淀能力

- `verify:production-config`：检查 `.env.production`、COS、ASR、上传目录和关键域名配置。
- `verify:deployment-health`：检查健康接口、登录入口、CSS 资源、3000 端口、PM2、Nginx 和 DNS。
- `verify:ai`：检查 AI 基础接口在无真实密钥场景下的稳定回退行为。

## 当前可沉淀 Agent 候选

### 部署上线体检 Agent

- 输入：`PUBLIC_URL`、`EXPECTED_HOST`、服务器项目目录。
- 动作：运行生产配置检查、部署健康检查、构建检查、PM2 状态检查。
- 输出：上线是否可继续、阻塞项、提醒项、下一步命令。
- 状态：已有脚本基础，适合沉淀。

### 构建后预览恢复 Agent

- 输入：本地端口、目标页面。
- 动作：运行构建后重启本地 dev server，检查页面、CSS、运行时错误。
- 输出：预览是否恢复、是否需要强刷浏览器。
- 状态：流程已重复出现，适合沉淀。

### 中文界面与角色一致性 Agent

- 输入：页面路径、角色账号清单。
- 动作：扫描用户可见英文、检查 7 类中文角色展示、检查菜单权限。
- 输出：残留英文、角色不一致、权限异常列表。
- 状态：规则清晰，适合后续沉淀。

### 移动端大陆浏览器兼容 Agent

- 输入：测试页面、浏览器矩阵、正式域名。
- 动作：检查 HTTPS、麦克风能力、上传、登录回调、底部导航遮挡。
- 输出：按浏览器列出通过/失败/需人工实测。
- 状态：需要正式 HTTPS 和真机环境，先作为清单。

## 构建完成汇报模板

每次构建完成后，汇报中增加以下小节：

```text
Agent 沉淀自查：
- 本轮是否出现重复流程：
- 是否具备稳定输入/输出：
- 建议沉淀形态：
- 是否需要新增脚本/Agent：
- 是否建议推送 GitHub：
```

## 推送策略

- 只要发生代码、脚本、文档修改，并且验证通过，应提示是否推送到 GitHub。
- 未经确认不主动推送。
- 如果服务器需要使用新功能，必须先推送，再让服务器执行 `git pull`。
